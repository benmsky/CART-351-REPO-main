WEEK 2: SEPT 21st

This week we started Python, and honestly I'm still a little confused by it. Coming from HTML, CSS and JavaScript, some of it feels familiar, like variables, if/else and comparisons, but the syntax is different enough that I kept second-guessing myself. No curly braces, no semicolons, and the indentation actually matters, which took some getting used to. I've also been sick this week, basically on "bedrest" (okay, that's a bit of an exaggeration), so I've actually had a lot of time to sit down and focus on this. To get myself moving, I ended up watching a few beginner Python videos on YouTube before starting the exercise. Seeing someone type things out and run them step by step helped more than just reading the slides, and it gave me the push I needed to actually open VS Code and start. From the Python Foundations I lecture, the string methods stood out the most, things like len(), .find(), .strip() and .upper(). Exercise 1 was basically a bunch of small puzzles using these, and running the file and comparing my output to the expected output made it feel less intimidating. One thing that tripped me up was that dividing with / always gives a decimal in Python 3... I also looked at the Real Python page on dynamic typing linked in the lecture. The idea that a variable doesn't have a fixed type and Python just figures it out when the code runs made sense to me after using type() in the exercise, even if I still don't fully get where that becomes a problem in bigger projects. I'm not fully comfortable with Python yet, but breaking it into small tasks seems to be helping... I'm praying I can retain what I'm learning.

WEEK 3: SEPT 28th

This week was the second part of Exercise 1, and I feel like Python is finally starting to click a little. Part A was all about lists, and a lot of it built on the string stuff from last week. Indexes starting at 0 I already knew from JavaScript, but slicing took me a second. greek[1:4] gives you the second through fourth items because the end number isn't included, and using a negative number like -2 to grab the last two items is honestly really handy. The task that made me stop and think was sorting. I first assumed I could just print a sorted version of the list, but the next task expected the sorted list with "radishes" added to the end, so I had to use .sort() which actually changes the list itself. It's a small thing but it showed me that the order of the tasks matters and that each one affects the next. .split() and .join() were also nice, turning "9/18/25" into "9-18-25" made it really clear how you can break a string apart and glue it back together. Part B was the fun part. We used the requests package to pull planet info from the Star Wars API, and then the Rich library to print it out as a coloured table in the terminal. It was kind of cool seeing real data come back from a website and show up as an actual table instead of a messy wall of text. I also learned that the API only sends 10 planets at a time, so to get the same 14 planets as the example I ended up asking for each planet by its number in a loop. On the side, I cleaned up my repository a bit. There was an extra old .git folder hiding inside my project folder that was confusing VS Code, so I got rid of it and added the new exercises to my homepage so everything is in one place. Compared to last week I feel a lot more comfortable, especially with loops and lists... next step is actually remembering all of this without looking back at my notes.
